# 图标竞赛裁决（m3-acceptance-round 任务 1.2）

三方向并行设计（A 几何极简 / B 节点链路 / C 字标动势），均交付 icon.svg + tray-icon.svg
+ 512/64/32/16 预览 + 黑底托盘参考 + 设计说明，且各自做了程序化像素核验（占比、最小
笔画、16px 剪影、tray alpha 分层）。评审由编排者以多轮视觉判读 + 各代理像素实证
交叉裁决（遵守「视觉判读不做几何事实来源」守则）。

## 候选与评语

| 维度 | A 折纸飞镖 | B 两点一弧流 | C 几何字标 a |
|---|---|---|---|
| 512px 造型 | 干净双色折面，负空间（尾缺口=入箭头）可读 | 真圆弧平滑无肘弯，三色阶旅程感成立，翼形明确 | Futura 式字架优雅，翼尾融入自然 |
| 16px 实测 | **最强**：飞镖剪影清晰，双色仍可分辨，尾缺口断口可见 | 可用但到极限：S 弧带+开口环两元存活，节点融入弧带 | 最弱：退化为「环+勾」，counter 仅 1-2px，读 a 需"配合" |
| 语义贴合 | 递出/接住一体（出入双读） | **最贴**：源节点→fabric 弧流→朋友端口开环+亮芯（127.0.0.1 落点） | 轨道滑出寓意好但需解释 |
| 差异化风险 | 与通用 "send" 图标同构（代理自认） | 与 OpenDWeb 四点连接器明确区分（两点单弧 vs 四点折线） | 字标在小尺寸语义衰减 |
| 托盘 template | 剪影清晰可辨 | 剪影可辨（弧带+环） | 环+竖笔可辨但弱 |

## 裁决

**胜者：B（两点一弧流 + 鸥翼光束）。**

理由：
1. **语义最贴合产品**：P2P「我的服务 → fabric → 朋友的开放端口」一图说尽，开口环的
   缺口朝向数据流、环内亮芯即 127.0.0.1 落点——叙事完整且不需解释；A 的出入双读
   好但依赖负空间细读，且与通用发送图标同构的差异化风险真实存在。
2. **16px 竞争力足够**：实测两元（弧带+开口环）存活、整体清晰；虽不及 A 的单一
   飞镖剪影强，但托盘 template 用其单色版剪影可辨，达标。
3. **品牌家族正确**：琥珀单色系三阶与 jixoai-ui hue 95 一致；与 OpenDWeb 图标
   构成「同一叙事宇宙、两种符号语言」（四点玻璃折线 vs 两点真圆弧），亲缘可辨而
   不混淆。
4. C 淘汰主因：16px 字腔消失导致 a 不可读，字标方向对 16px 托盘产品是结构劣势。

拷贝），`pnpm app:icons` 再生全平台资产；A/C 稿随 change 目录留档。
